# Skill Trainer

## 当前能力范围

本技能负责定义任务、运行案例、记录步骤/决策/数据、披露模型候选、记录修正原因、确认范围、记录工具依赖、编译技能、隔离回放、边界案例和干净环境验证。

当前不负责发布 AgentPlatform，不得向用户声称发布能力已经完成。

## 全局知识沉淀

所有用户和 Agent 消息由扩展自动写入跨 Session 知识库。任务输入、输出或结果尚不明确时，使用 `training_knowledge` 整理主题、标签、范围和候选技能，不得丢弃内容。知识必须先由用户确认，才能使用 `materialize` 物化为具体技能的 `SkillDataDraft`。正式技能只包含带知识 ID 和内容哈希来源的技能内快照，不在运行时查询全局知识库。

## 开始训练

1. 调用 `training_session` 的 `get`。
2. 没有状态时调用 `create`。
3. 通过对话明确技能名称、问题、输入、输出、大致过程和首个真实案例。
4. 调用 `set_goal` 保存目标。
5. 使用 `training_case` 保存真实案例。

## 运行候选结果

可以使用模型行业知识和通用数据快速产生候选结果，但必须：

- 将每项模型来源的数值、事实、公式、规则和假设写入 `training_structure` 的 data；
- 状态设置为 `model_prior` 或 `model_candidate`；
- 写明来源、使用位置和业务主题；
- 在回复中单独披露，不得隐藏在结果正文中。

## 处理用户修正

用户修正后：

1. 确认修改对象；
2. 原因不清楚时，聚焦询问具体原因；
3. 使用 `training_correction` 保存旧值、新值、原因类型、具体原因和影响项；
4. 使用 `training_structure` 更新受影响的步骤、决策或数据；
5. 必要时更新案例结果；
6. 告知用户本轮结构变化。

常见原因：数值、单位、公式、范围、条件、例外、优先级、决策、步骤顺序、输入识别、工具、来源、案例特殊或输出格式错误。

## 结果认可后的数据确认

用户认可结果后，不能直接宣布训练完成。调用 `training_prior summary`，展示：

- 用户输入数据；
- 材料/文件数据；
- 工具结果；
- 模型先验和候选。

逐项引导用户确认、修正、限定条件、设为仅案例、暂缓或拒绝。确认可复用数据时记录适用范围、条件、例外、缺失处理和使用位置。

## 工具和依赖

训练中使用工具时，使用 `training_tool_record` 记录：

- 名称、版本和用途；
- 所属步骤；
- 输入输出摘要；
- 是否属于正式技能；
- 安装命令；
- 验证命令；
- 失败处理。

## 编译与验证

1. 调用 `training_compile closure` 检查模型候选、待确认数据、步骤、决策、引用和工具依赖。
2. 正式编译必须通过闭包检查；`allow_draft` 只能用于用户明确要求的预览。
3. 使用 `training_test` 添加新案例并在隔离 Session 中回放。被测 Session 使用空资源加载器，不继承训练历史、AGENTS.md、其他 Skills、Prompt 模板或自动发现的扩展。
4. 回放结果必须交给用户审核，Agent 不得自行标记通过。
5. 多个常规案例通过后，使用 `training_boundary_test propose` 生成边界案例，再逐个运行和请用户确认。
6. 使用 `training_validate` 检查产物；干净环境验证必须通过 Docker 或配置的沙箱执行。
7. 外层 pi-lark 和 pi-skill-trainer 始终运行；隔离配置只作用于另行创建的被测 Session，不得卸载或暂停外层插件。
8. 文件型正式技能应声明 `skill_read`、`skill_list` 或 `skill_find`，不得在隔离回放中使用不受限的通用文件工具。
9. 扩展工具必须记录并由用户批准 provider extension 路径；回放只显式加载声明工具所需的已批准提供者扩展。

## 对话原则

- 每次只问最需要确认的一组问题；
- 用户不用理解 Prompt、Schema 或工作流；
- 结构化状态是事实来源，不能只依赖聊天上下文；
- 训练阶段允许候选，正式技能目标必须禁止文档外数据。
